- [ ] 2. custom module の純粋ロジック(ハンドシェイク・索引・適用プラン)を実装する
- [x] 2.1 (P) マニフェストハンドシェイク状態機械を実装する
  - `requesting`(採用まで再送継続)/ `settled`(採用済み・再送停止)の 2 状態 + 採用済みマニフェスト保持。初期状態は `requesting`、タイマー・送受信を持たない tick 駆動(既定間隔 2 秒)の純粋ロジックとする
  - 受信ペイロードは JSON パース → shared の `ManifestSchema.safeParse` を唯一の受け入れ判定とし、採用時のみ最新版を置換する。拒否時は理由(パース不能 / スキーマ違反)と zod issue 詳細を返し、前回採用分と `requesting` 状態を維持する
  - 同一理由の連続拒否は `isRepeat` として返し、ログ出力の抑制判断を呼び出し側に委ねる
  - 到達性回復の通知で `settled` からも `requesting` へ戻し、最新マニフェストを取得し直す。同一内容の再採用は冪等
  - 単体テスト: 初回要求 / 間隔再送 / 採用で再送停止 / 不正時の不採用・保持継続・isRepeat / 回復で再開 / 再採用の冪等が緑になっている
  - _Requirements: 1.1, 1.2, 1.3, 1.4, 1.5, 2.8_
  - _Boundary: ManifestClient_

- [x] 2.2 (P) レイアウト索引の構築ロジックを実装する
  - レイアウト JSON(unknown 値)を再帰走査し、`address` 明示ウィジェットは当該アドレス、`address: 'auto'` / 省略は O-S-C 規約どおり `/<id>` をキーとして address → widgetId 索引を構築する
  - 動的生成領域のコンテナ配下は索引から除外する(除外コンテナ id は引数で与えるデータ駆動)
  - 同一アドレスの重複は先勝ち + 警告リストへ記録し、不適合入力は空索引 + warning で返す(例外を投げない)
  - 単体テスト: 明示 / auto アドレスの索引化・動的コンテナ配下の除外・重複警告・不正 JSON の空索引が緑になっている
  - _Requirements: 2.1, 2.9_
  - _Boundary: LayoutIndex_

- [x] 2.3 (P) 到達性計測に回復遷移の通知を追加する
  - pong 採用時の戻り値を「採用可否 + 喪失状態(連続喪失 1 以上)からの回復か」を含む結果型へ拡張する
  - 計測仕様(未応答 1 件保持・2 秒ウィンドウ・破棄規則)とスナップショットは Phase 1 のまま不変とし、既存の呼び出し箇所と単体テストを戻り値変更に追随させる
  - 単体テスト: 喪失 1 以上からの採用で回復 true、非喪失時は false、既存の計測テストが引き続き緑になっている
  - _Requirements: 1.3_
  - _Boundary: PingMonitor_

- [x] 2.4 ウィジェット対応表と適用プラン生成を実装する
  - 対応表データ: manifest の widget 種別 → O-S-C ウィジェット型 + 基本プロパティ雛形(fader / button push / toggle は button mode toggle 0/1 / xy / text 表示専用)、エントリ type → 値同期の OSC 型タグ(bool は i 0/1、b は同期対象外)、将来の widget 省略時フォールバック表 — いずれも定数データでありコード分岐を持たない
  - 既存ウィジェット更新: 索引にあるエントリのみ label と(あれば){min, max} 形式の range を編集コマンド化し、それ以外のウィジェット・プロパティには触れない(対応エントリなしウィジェットは不変)
  - 動的生成: 索引にないエントリを group ごとの子パネル + 見出しへ集約し、動的コンテナの widgets 配列を丸ごと構築する単一編集コマンドに一本化(常にちょうど 1 件 — 再受信時の消滅エントリ削除が全再生成で自然に成立し、手動配置は取り除かれない)。生成 props は決定的 id 変換・エントリと一致する address・label・range・default(現在値)を含める
  - 値同期: 既存・動的の区別なく default があるエントリの表示同期列を生成(b 型はスキップして warning)。同一入力 → 同一プランの決定的純粋関数とする
  - 単体テスト: 既存のみ / 動的のみ / 混在 / group あり・なし / 再受信での削除 / range・default 省略 / b 型スキップ / 対応なしウィジェット不変が緑になっている
  - _Requirements: 2.1, 2.2, 2.3, 2.4, 2.5, 2.6, 2.7, 2.8, 2.9, 3.1, 6.4_

- [ ] 3. mock-unity のシナリオ駆動マニフェスト応答を実装する
- [x] 3.1 (P) シナリオランタイムとシナリオデータを実装する

  - 単体テスト: プレースホルダ展開・キャラ名の生成 / 固定・値ストア反映・生成マニフェストのスキーマ適合・オーバーライド応答が緑になっている

- [x] 3.2 レスポンダにマニフェスト応答と値ストア反映を追加する

- [x] 4.2 マニフェストハンドシェイクを runtime へ配線する
  - runtime deps へクライアント配信・app イベント購読・レイアウト読み込みを DI 追加し、O-S-C グローバル(receive / app / settings)の型宣言とエントリポイントからの注入を実装する
  - init でレイアウト索引を構築(失敗時は空索引 + エラーログで継続)し、既存の 2 秒 tick に相乗りして要求要否を評価 → 必要なら設定宛先へマニフェスト要求を送信する(init 直後にも 1 回即時評価し初回要求を待たせない)
  - 受信フィルタ拡張: マニフェスト受信は検証へ渡して swallow(採用 / 拒否をログ。同一理由の連続拒否は抑制)、pong の回復遷移で再要求を開始する。システムメッセージのウィジェット素通し禁止(Phase 1 の swallow 規則)を維持する

- [x] 4.3 マニフェスト適用の配信経路を配線する
  - 新マニフェスト採用時は適用プラン(編集コマンド列 + 値同期列)を全クライアントへ、クライアント接続完了(sessionOpened)時は当該クライアントのみへ順に配信する(ウィジェット状態はクライアントごとに存在するため)
  - `/EDIT` 配信は props の JSON 文字列化 + opts `{noWarning: true}` を常に付与し(未保存ダイアログ抑止)、clientId オプションは指定時のみ渡す(undefined 渡し禁止 — OSC 引数と誤認される)
  - 値の表示同期は receive 経由のみを使用し `/SET` を使わない(送信なしの表示更新 — フィードバックループ禁止)。値の確定は引き続き Unity からのエコーバックのみに依拠する
  - イベントハンドラ・フィルタ内は try/catch で保護し、stop / unload での解放(Phase 1 規律)を維持する
  - バンドル再生成後、O-S-C headless + mock-unity(標準シナリオ)+ ブラウザのループバック構成で、キャラ名入りラベル・動的ウィジェット・現在値が UI に現れる状態になっている
  - 単体テスト(fake deps): 採用 → 全クライアント配信 / sessionOpened → 当該クライアントのみ配信 / 値同期が receive 経路であることが緑になっている
  - _Requirements: 1.6, 3.1, 3.2, 3.5_
